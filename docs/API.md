# Voyage API Reference

**Base URL:** `http://localhost:8080`  
**Request/response format:** JSON, except for text error responses and empty DELETE responses.

## Endpoints

| Method | Endpoint | Request body | Response |
|---|---|---|---|
| `POST` | `/api/trips` | Trip JSON | Saved Trip, `201 Created` |
| `GET` | `/api/trips` | None | List of trips, `200 OK` |
| `GET` | `/api/trips/{id}` | None | Trip, `200 OK`; missing ID → `404` |
| `PUT` | `/api/trips/{id}` | Updated Trip JSON | Updated Trip, `200 OK`; missing ID → `404` |
| `DELETE` | `/api/trips/{id}` | None | `204 No Content`; missing ID → `404` |
| `GET` | `/api/destinations/attractions?query=Goa` | None | List of nearby attraction objects |
| `POST` | `/api/trips/{tripId}/itinerary/generate` | Array of selected attractions | Saved itinerary |
| `GET` | `/api/trips/{tripId}/itinerary` | None | Saved itinerary; missing → `404` |
| `POST` | `/api/trips/{tripId}/budget/calculate` | Array of selected attractions | Budget breakdown |

The frontend also uses `GET /api/destinations/search?query=...` for destination details. Its exact response shape is defined by the destination-search controller/DTO.

## Request and response examples

### Create trip — `POST /api/trips`

**Request:**
```json
{
  "title": "Goa Getaway",
  "destination": "Goa",
  "startDate": "2026-11-05",
  "endDate": "2026-11-07",
  "budget": 15000,
  "description": "Explore Panaji"
}
```

**Example response (`201 Created`):**
```json
{
  "id": 1,
  "title": "Goa Getaway",
  "destination": "Goa",
  "startDate": "2026-11-05",
  "endDate": "2026-11-07",
  "budget": 15000,
  "description": "Explore Panaji"
}
```

The `id` is generated by the database; `1` is only an example.

### Update trip — `PUT /api/trips/1`

Send the full set of editable trip fields:
```json
{
  "title": "Goa Getaway — Extended",
  "destination": "Goa",
  "startDate": "2026-11-05",
  "endDate": "2026-11-08",
  "budget": 18000,
  "description": "Updated plan"
}
```

The response contains the updated Trip, including its existing ID. Delete the trip with `DELETE /api/trips/1`; success returns `204 No Content` and no response body. The service deletes any linked itinerary before deleting its trip.

### Attraction discovery — `GET /api/destinations/attractions?query=Panaji`

**Example item** (actual results depend on Wikipedia):
```json
{
  "name": "Example Museum",
  "description": "Nearby place listed on Wikipedia",
  "latitude": 15.0,
  "longitude": 73.0,
  "category": "Museum",
  "imageUrl": null
}
```

`imageUrl` may be null if no image is available. Coordinates above are illustrative.

### Itinerary generation — `POST /api/trips/1/itinerary/generate`

**Request:**
```json
[
  { "name": "Example Museum", "category": "Museum" },
  { "name": "Example Garden", "category": "Park" }
]
```

**Example response shape:**
```json
{
  "id": 1,
  "trip": {
    "id": 1,
    "title": "Goa Getaway",
    "destination": "Goa",
    "startDate": "2026-11-05",
    "endDate": "2026-11-07",
    "budget": 15000,
    "description": "Explore Panaji"
  },
  "items": [
    {
      "date": "2026-11-05",
      "attractionName": "Example Museum",
      "description": "Visit Example Museum",
      "startTime": "09:00",
      "endTime": "11:00"
    }
  ]
}
```

The service distributes visits across available trip days, determines duration from category, avoids the lunch period and adds a 30-minute buffer after each visit. Actual generated dates/times depend on the request and scheduling logic.

### Budget calculation — `POST /api/trips/1/budget/calculate`

**Request:** the same array of `{ "name", "category" }` objects used for itinerary generation.

**Example response:**
```json
{
  "totalBudget": 15000,
  "attractionCost": 300,
  "hotelBudget": 14700
}
```

These values illustrate two attraction categories: Museum (₹200) and Park (₹100), according to the current budgeting rules. The hotel budget equals the entered total minus estimated attraction costs, floored at zero. Food, transport and live hotel rates are not included in this backend result.

## Input validation and errors

- Required Trip fields: `title`, `destination`, `startDate`, `endDate`, `budget`.
- Blank `title` or `destination` fails validation; negative `budget` fails validation.
- The itinerary service rejects missing dates, an end date before the start date, and an empty or invalid attraction list.
- `TripNotFoundException` produces **404 Not Found**.
- Validation errors and recognized illegal arguments produce **400 Bad Request** using `GlobalExceptionHandler`.
- Error response bodies from the current handler are plain text, for example `Trip not found with ID: 999`.

**Note:** `Trip` field validation does not itself enforce end date ≥ start date. The itinerary service checks that condition during itinerary generation.
